## 项目目标与实现

系统通过服务器终端 CLI 接收学生材料，形成可追溯画像，澄清必要信息，结合职业知识生成规划，并按反馈调整表达详略。唯一产品入口为 `project/assistant_cli.py`；最终规划使用 DeepSeek，本地模型使用既有 CUDA 权重，文件解析、规则校验和关键词检索可离线执行。

感知层处理文本、文档及可选图片等材料。需求引导层使用本地 Qwen3-4B 提出有来源的候选信息，执行层校验字段、证据和问题，区分未提供、未知、拒答、明确没有与矛盾。编排器恢复历史画像，将确认后的答案送入知识检索和最终规划提示词。

最终规划包含目标岗位、能力差距、30/90/180 天路线、学习资源、下一行动与风险。系统保存脱敏后的会话、交互和运行日志。反馈适配初版使用本地模型选择原规划内容的分组、顺序和详略，程序渲染源字段并保留原事实与版本关系，避免自由改写新增未经确认的信息。

## 局限与剩余工作

目前 GPU 引导仅有三例小样本，尚不能代表长期稳定性或广泛中文表达。需求引导的模型可能提出重复问题，执行层负责拦截。文档受现有解析长度约束，扫描 PDF 自动视觉解析仍未实现；音频需要已有本地权重。视觉与文本模型同时驻留的显存需求尚未单独测量。

反馈适配限制为引用布局，不自由增加解释。无法在保留必要信息的前提下满足详略方向时保持原版本并说明；不可因此宣称用户负担降低或满意度提高。初版每个活跃规划接受一次反馈，重复请求可重放，持续多次调整未实现。

剩余顺序：审阅授权发布验收记录与报告更新 → 收集人工原文意见与独立评分 → 根据学校模板定稿。不重复已通过的真实演示；字数变化不代表建议适用性或满意度。学校截止日期、模板及硬性成果要求待负责人确定后决定最终排期。

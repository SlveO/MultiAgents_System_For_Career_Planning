# 本地反馈输出适配最小方案

日期：2026-10-02。主责：服务器 Agent。已接收发布 main `3308d65c3941e31c0c60a174e9d4fc37f22c8989`；工作分支 `codex/local-feedback-adaptation`。需求引导的 85 项离线测试和三例 GPU 验收作为已有证据，本任务不重复运行。本文保存合同检查与设计；实现和最新验收状态见[实施记录](local-feedback-adaptation-implementation.md)。

## 当前入口与缺口

`core/feedback.py` 已将用户输入映射为“过短 / 合适 / 过于详细”。CLI 展示规划后调用 `submit_feedback`；该方法只写反馈和 JSONL，再删除内存中的待反馈规划，返回 bool。SQLite 反馈表仅有选择、rating 和时间，没有原规划版本引用或改写结果。`CareerPlanResponse` 包含完整事实与建议，但没有输出版本合同。

因此，不能只把新的表达返回给 CLI：必须在消费待反馈记录前取得原始规划，明确版本关系，并保存用户实际看到的新版本。“合适”继续沿用原表达，rating 仍为空，不把详略选择当满意度分数。

## 最小合同与接入

1. 为展示版本增加独立合同：原规划 ID、版本号、原表达摘要哈希、反馈选择、展示文本、适配状态和错误类别。规划画像、岗位、差距、路线、资源、约束及风险保持原合同值；适配只改变展示表达。
2. 本地模型复用已有 Qwen3-4B 的惰性 CUDA 加载策略，配置路径与设备显式指定。模型选择原规划中带稳定 ID 的内容如何分组、排序和展示，输出受限的引用/详略结构；渲染器使用原字段文本。初版不允许模型添加自由事实、数值、岗位、技能或来源 URL。
3. “过短”展开已有路线、交付物、指标和下一行动；“过于详细”压缩重复表达，仍显示目标、必要约束和风险；“合适”原文不变且不调用模型。通过真实可见文本检查详略方向，不以字数变化推断满意度。
4. `submit_feedback` 保留兼容记录能力，新增明确的适配结果接口供 CLI 调用。SQLite 增加独立输出版本记录，原交互不覆盖；JSONL 同时记录原规划关联、新版本和失败状态。重复反馈请求不得产生重复版本，适配失败保留原版本并明确告知。

## 离线验收与下一动作

交付物：展示合同、本地适配器、编排/CLI/存储接入及聚焦回归测试。先用模拟模型/规划客户端覆盖三档反馈、用户能看到新版本、事实合同与版本来源不变、重复提交、未知引用、非法输出和模型不可用。确保“合适”零模型调用；失败不覆盖原文本或冒充已适配。

依赖：已发布需求引导、现有 Qwen3-4B；期限待负责人提供。下一动作是实施上述合同和离线流程，再另行授权验证真实 GPU 适配质量。反馈实现的提交/发布需审阅后的明确授权；本方案未调用 GPU/API、未安装依赖、未修改私有配置。

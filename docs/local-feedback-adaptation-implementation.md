## 行为与合同

- 原 `CareerPlanResponse` 保留事实字段，附加规划 ID 和第 1 版展示记录。反馈改变独立 `OutputVersion`，不覆盖原交互或原建议。版本带父版本、事实摘要、原表达摘要和引用条目，可追溯到同一规划。
- `output_adaptation.py` 从原规划建立内容目录。本地模型只返回 section、item_ids、style；不接受自由文本或额外字段。渲染器读取原字段，拒绝未知、重复、错误分组的引用，并强制保留目标、路线目标、下一行动、约束、风险和待确认信息。路线仍按原时间顺序展示。
- “过短”展开已有内容；“过于详细”保留必要项、压缩表达；“合适”原文不变、零模型调用。只有文本长度朝要求方向变化才生成第 2 版，否则说明无法进一步调整并沿用原文。不把增加标题当作扩充，也不以字数变化声称满意度提高。
- `LocalFeedbackModel` 复用既有惰性 CUDA 加载与有界 JSON 生成，输出合同独立。`FEEDBACK_MODEL_PATH` 留空时仅复用显式配置的 `GUIDANCE_MODEL_PATH`；没有隐式权重选择、下载、CPU 回退或 API 适配。
- CLI 在成功时显示新版本全文，失败时说明原规划保留并返回非零。非调试展示隐藏版本哈希和引导内部记录，避免把实现字段加入用户流程。

## 存储与恢复

SQLite 增加 output_versions 与 feedback_adaptations 表，旧表不删除。反馈、结果和新增版本在一个事务内写入；rating 仍为空。JSON 备用存储同样保存版本与请求结果，并使用同目录临时文件原子替换，失败时保留旧数据。

默认反馈请求标识绑定会话、规划和选择，同一请求重复调用或重启后调用均复用已保存结果，不再次生成、不重复记反馈。标识不能被另一规划或另一选择复用。初版每个活跃规划处理一次反馈；之后支持原请求重放，新一轮调整需生成新规划。旧 `submit_feedback` 保留仅记录兼容接口，CLI 使用 `adapt_feedback` 完成展示适配。

JSONL 记录原、新版本与适配状态；重试按请求标识去重。若数据库写入已成功但日志失败，恢复后可补写版本关联日志，不重新调用模型。成功、未改变、失败三种状态分别保存，模型错误只保留稳定类别，避免泄露私有路径。

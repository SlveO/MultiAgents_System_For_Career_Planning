## 检查结论

- `project/assistant_cli.py` 在创建编排器、感知材料前询问固定八题；非空 `--answers-json` 会跳过整组问题，即使答案不全。
- `project/core/intake.py` 的八个维度为学历、专业、技能、兴趣、目标岗位、时间、城市/行业偏好、限制。未知、拒答和“无”都被清空，无法区分未提供与明确回答。时间取首个整数，不能可靠表达范围、负数或小数。

- 规划提示词已有画像，但没有回答来源和未解决状态；知识检索只使用原始目标与文本，未使用补充答案。普通与流式路径分别编排，接入需共用准备结果，避免重复感知或询问。

## 最小实现

1. **先准备再追问。** CLI 先构建请求，由编排器完成一次材料感知、历史读取与初始画像准备，再交给引导模块。普通与流式规划复用同一准备结果。保留八维度作为字段映射和问题模板，不再要求逐题询问。`--answers-json` 先纳入记录再判断缺口；`--no-follow-up` 禁止交互，但仍记录已有答案与未解决状态。
2. **扩展现有合同。** 在 `schemas.py` 增加引导状态及回答记录：字段路径、状态（missing/known/unknown/refused/explicit_none/conflict）、候选值、证据引用、问题 ID、原始回答、轮次和来源。旧画像无记录时按实际非空字段迁移；不得把空列表推断为明确没有。学历别名统一映射，时间采用明确的非负数值校验，不猜测范围。原始回答沿用现有脱敏持久化，不额外写明文日志。
3. **本地模型理解，规则约束执行。** 新增惰性加载的本地文本引导适配器，候选使用已有 Qwen3-4B-Instruct-2507；显式配置模型路径和 CUDA 设备、仅本地文件加载、禁止 CPU 回退或隐式下载。模型根据目标、材料证据、已有字段及回答记录提出结构化候选事实/矛盾/下一问题；Pydantic 校验字段白名单、引用及输出，模型不能直接覆盖画像。规则决定是否允许提问、去重和停止，不把规则单独称为本地模型引导完成。
4. **针对性单题循环。** 优先处理影响目标和可执行性的矛盾，再补目标、能力、时间等必要缺口；模糊目标允许澄清，岗位目标不能直接从泛化的 user_goal 推断。已知字段不重复问；未知、拒答、明确没有均视为已回答，不因空值再次追问。冲突保留双方来源，用户确认后才更新；用户明确更正可替换旧值。去重键包括字段和冲突证据，避免换措辞重复问。无可问项、用户停止或达到可配置上限即结束；建议初版上限 4 轮，仅为方案参数，不继承成员 C 的 8 轮规则。空回答也记录尝试，不原地循环。
5. **回答进入实际规划。** 完整恢复历史画像和字段状态，合并已确认答案；使用确认后的目标/技能补充检索查询。画像、回答证据摘要和未解决项进入 DeepSeek 实际提示词，并随请求/响应写入既有 SQLite/JSONL。未解决冲突不默认为已确认事实。跳过、上限、模型错误都保留停止原因；模型不可用或输出非法时明确展示，可选择结束引导并带不确定性继续，不静默改用 API 或规则冒充模型。

## 离线验收与交付边界

交付物：引导模块、本地模型适配器、合同扩展、CLI/编排接入和离线回归测试。以注入假的引导模型和假的规划客户端验证：

- 缺失、未知、拒答、明确无技能及零时间预算语义不同；时间范围或非法值不会误写。
- 已回答内容和完整历史画像不再重复问；目标模糊、材料冲突可针对性澄清；冲突确认后才改变事实。
- 部分 JSON 答案补问其余必要项；跳过、空回答、轮次上限、非法模型 JSON 和模型加载失败均可控终止。
- 普通/流式路径感知只执行一次；补充答案进入检索查询、实际规划提示词与脱敏持久化记录，来源可追溯。
- 替换旧测试中“必须问完八题”“拒答等同缺失”的断言，保留八字段映射兼容测试；验证测试不会触发真实网络或模型加载。

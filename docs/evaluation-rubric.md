# 主研究实验评分与契约

## 适用范围

本文件由负责人维护，用于三组架构对照和 2/3 轮预实验。案例字段以
`dataset/research_case.schema.json` 为准，模型、生成参数、共享提示词和
输出结构以 `dataset/research_protocol.json`、`research_evidence.schema.json`、
`research_decision.schema.json` 和 `research_plan.schema.json` 为准。已确认
选择及变更过程记录在 `docs/research-decisions.md`。成员不得在各自分支中
重命名字段或修改评分规则；必要变更由负责人确认并同步更新契约。

## 固定输入与输出

每组必须使用相同的 `case_id`、用户目标、固定画像、职业知识片段、最大
输出长度和确定性生成参数。单体组规划器直接接收原始媒体；模块化组的 2B
感知器接收相同媒体，4B 推理器只接收结构化证据。决定性媒体证据不得在
文本画像中重复。

规划输出必须包含目标岗位、差距、30/90/180 天路线、学习资源、下一步
行动、风险、用户建议、置信度、证据状态、证据引用和知识 ID。整段响应
必须直接通过 `json.loads` 和 JSON Schema 校验；不得剥离 Markdown、自动
修复或格式重试。无效原始响应只供排查，不交给评分员补救评分。

## 五维盲评量表

每项使用 1–5 分。2 分和 4 分表示介于相邻锚点之间。

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 证据正确性与忠实度 | 关键事实与媒体冲突，或大量无依据推断 | 核心事实大体正确，但有遗漏、弱引用或轻微推断 | 关键事实完整准确、可定位，规划结论均能追溯且无无依据补充 |
| 职业相关性 | 岗位与画像、目标或媒体证据明显不匹配 | 岗位基本合理，但只使用部分画像或证据 | 岗位、差距和建议均直接结合画像、知识与媒体证据 |
| 可执行性 | 仅有口号或抽象建议，无时间、产出或衡量方式 | 有阶段行动，但部分产出或指标不明确 | 30/90/180 天均有具体行动、交付物、指标，并符合时间与限制 |
| 完整性 | 缺少三个及以上必需部分，或主要路线不可用 | 结构基本完整，但有一个部分明显薄弱 | 所有必需字段有效，三个阶段完整，风险和下一步行动明确 |
| 详略适配 | 过短无法执行，或冗长且大量偏题 | 长度可用但仍有模板化、重复或轻微失衡 | 信息密度适合案例复杂度，重点突出，无关键遗漏或无关展开 |

若输出包含与媒体直接冲突的关键事实，“证据正确性与忠实度”最高 2 分。
若 30/90/180 天任一阶段缺失，“完整性”最高 2 分。

## 评分流程

1. 负责人为输出生成随机 `output_id`，隐藏组名、模型名、轮次和延迟；每位
   评分员看到的输出顺序单独随机化。
2. 评分员可查看匿名案例的原始媒体、固定画像、固定知识片段和最终规划，
   不得查看实验组、模型、协作轮次、自动指标或另一人的评分。
3. 两名评分员先独立完成评分。任一维度相差超过 1 分时，由两人根据预期
   证据重新核对；仍不一致时由负责人只依据量表裁决并记录理由。
4. 有效输出的五项裁决分取平均，得到该例五维平均分。主分析使用包含失败
   惩罚的 `effective_five_dimension_mean`：无效 JSON 或推理失败记 1 分，
   不从分母排除；同时单独报告有效率和仅限有效输出的各维度结果。
5. 证据正确性是关键约束指标。报告五个维度的均值、标准差、配对差值、
   平均评分差、裁决次数和失败数；总平均分不得代替各维度明细。
6. 自动记录 JSON 有效性、延迟、峰值显存、错误、实际协作轮数和降级状态；
   自动指标不提供给盲评员。

评分表至少包含：`case_id`、`output_id`、匿名 `rater_id`、五项分数、证据
问题、评分备注、是否需裁决、裁决分和裁决理由。运行记录另存有效性、错误
和性能指标。评分员不得填写个人身份信息。

## 2 轮与 3 轮选择规则

在相同 6 个案例、相同模型修订、提示词、种子和知识片段下分别运行最多
2 轮与 3 轮。轮次指“一次证据请求加一次感知器增量响应”，充分性决策调用
不计轮次。仅当 3 轮同时满足以下条件时，主实验采用 3 轮：

- 没有新增推理失败或无效 JSON；
- 证据维度平均提高至少 0.50 分；
- 五维平均提高至少 0.25 分；
- 至少 3 个案例提高，且没有案例的证据分下降超过 1 分。

否则主实验冻结为 2 轮。该预实验只比较点估计，不做显著性检验，也不并入
正式实验。负责人将选择写回
`research_protocol.json` 的 `primary_round_cap`，提交后才能开始 20 案例、
三组共 60 次正式运行。延迟和显存只作为取舍说明，不改写质量分数。

## 验收

- 案例、协议及三个输出 Schema 可解析，契约回归测试通过；
- 两名评分员能只凭本文件对同一输出独立打分；
- 评分文件、模型输出和自动指标分开保存；
- 模板、Fake 模型或降级输出不计入真实模型质量结论。

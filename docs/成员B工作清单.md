## 三、验收标准

- [ ] 真实密钥只存在 `DEEPSEEK_API_KEY` 环境变量，不出现在仓库、日志、README 或代码
- [ ] 20 个固定样例中，画像 JSON 解析成功率 ≥ 90%
- [ ] 模型不虚构用户未提供的经历；无法确定时写入 `missing_fields`
- [ ] 规划必须引用 `retrieved_jobs` 中的事实，包含方向、差距、阶段行动
- [ ] API 超时、限流、余额不足、JSON 错误均有明确提示和日志

## 六、关键约定与红线

- **接口**：B 定义 SessionState 中 `user_profile` 字段（专业、年级、技能、兴趣、目标、偏好、缺失字段）和 `plan` 对象；A 只负责传递与持久化。负责人第1周第2天冻结 Schema，改公共字段须经负责人确认
- **依赖**：接收 A 传入的 `raw_input`、`retrieved_jobs`、`feedback`；C 提供的职业知识字段说明、追问规则和测试样例。B/C 模块**不得**自行读取终端输入
- **模型配置**：deepseek-v4-flash，Base URL `https://api.deepseek.com`，默认非思考模式，调用前通过 `/models` 确认可用
- **JSON 稳定性红线**：20 例成功率低于 90% 时，启用 JSON 模式 + 示例 + 校验 + 一次重试；再失败走模板输出（模板输出不得混入实验数据）
- **数据纪律**：预存演示样例、模板化输出、人工改写结果不得计入实验数据；失败样例必须保留并说明原因
- **降级表述**：降级内容在报告中必须写为"原型实现""简化验证"或"后续方案"
